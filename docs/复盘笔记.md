# 表桥项目复盘

## 为什么做

原始命题针对人力行政跨系统表格转换。源系统导出的字段、编码、日期和目标导入列序不一致，人工拷贝、清洗和核对容易出错；异常处理还需要业务人员参与。原始要求见同目录的参考命题。

以下阶段依据当前工程和验收材料整理，属于工作回顾，不是 Git 历史。

1. 实现人事场景：年假抵扣、事假转换、加班筛选，保留为 `/legacy` 工作台。
2. 扩展通用工作台：读取实际源 Schema 和目标模板，通过模型生成映射、约束与清洗代码，支持两表合并及精确左关联。
3. 加入受限执行、异常修正、导出门禁、格式回读、审计和流程保存复用，形成可验证的处理闭环。
4. 2026-10-12 完成有效 DeepSeek 调用实测：原始表头和变化表头两组案例，包含输入数值扰动和三种导出格式校验。早期人事验收的 401 属历史记录，最新通用验收已成功。

## 哪些设计值得保留

- 使用当前文件的真实表头生成计划，变化表头实测避免只适配固定演示字段。
- 模型生成结果先由人核对，再在隔离进程中执行；受限 AST 解释器不开放文件、网络、导入模块或任意属性访问。
- 异常未解决时阻止导出；人工决策进入审计。保存流程复用规则，不把某次人工修正的手机号写成模板常量。
- 用实际回读核对 XLSX、BIFF8 XLS 和不同编码 CSV。保留文本工号和前导零，以 Decimal 处理业务数值。
- 同时保留输入哈希、源行定位、筛选/去重理由、转换代码和导出结果，便于解释“为什么得到这条结果”。

## 从实测得到的经验

- 自然语言要求过于简略时，模型可能提出澄清问题。明确日期格式、地址拆分和冲突处理口径后再生成，不跳过澄清与确认门禁。
- “生成成功”不等于“导入成功”。模拟数据上的清洗、格式回读和正式目标系统接收是不同验收环节。
- 申报文字与实现版本需要同步。当前申报书仍为较早的人事场景底稿，评审应结合新版范围说明、源码和真实演示阅读。
- 成片应该对应一次真实运行。当前视频运行编号为 `bdbccdc0a5aa4973a6b886f940e55dea`，7 条输入、5 条输出、异常 1 → 0，导出审计可核对。
- 文件改名会让说明和校验失效。归档使用当前文件名，重新生成清单和整包；不重复收录相邻解压目录。
