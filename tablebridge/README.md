# 表桥 跨系统表格处理智能体

面向 ERP、CRM、OA、HR 的本地表格转换应用。通用工作台由 LLM 分析实际 Schema、动态生成受限 Python 清洗代码，在隔离进程中执行并校验，遇到异常暂停导出，人工修正后输出 XLSX、真实 XLS 2003 或指定编码 CSV。成功流程保存为本地转换模板。

原有年假抵扣、事假拆分和加班筛选工作台保留在 `/legacy`。

演示数据均为模拟，不包含企业正式数据。真实目标 HR 导入尚待命题方模板与测试环境验收。

## 启动

需要 Python 3.11 或以上。本机 Web 工作台已在 macOS 和 Python 3.12 验证。Windows 原生桌面入口及打包脚本已提供，尚未做 Windows 实机验证。

Windows 桌面：双击 `桌面启动.bat`，首次自动安装依赖后打开 pywebview 原生窗口；首次运行可能需要 Microsoft Edge WebView2 Runtime。配置放在 `%LOCALAPPDATA%\TableBridge\.env`（开发启动也可沿用工程目录 `.env`），结果和模板放在 `%LOCALAPPDATA%\TableBridge\data`。运行 `构建Windows.bat` 可生成 `dist\TableBridge\TableBridge.exe`，需要在 Windows 上构建。

下面是浏览器版启动方式，也用于跨平台开发和验收。

macOS 或 Linux：

```bash
cd tablebridge
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Windows：

```powershell
cd tablebridge
py -3 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python app.py
```

打开 http://127.0.0.1:8877 。也可以双击 `启动.command` 或 `启动.bat`。首次安装依赖需要网络；安装完成后，本地计算和界面不依赖外部网络或 CDN。端口可通过 `BRIDGE_PORT` 环境变量修改。

## 模型配置

复制 `.env.example` 为 `.env`，填写自己的 OpenAI-compatible Chat Completions 服务配置：

```dotenv
BRIDGE_API_KEY=自己的密钥
BRIDGE_BASE_URL=https://api.deepseek.com/v1
BRIDGE_MODEL=deepseek-chat
```

这里的默认值是配置示例，请按自己的服务填写实际模型标识。`.env` 配置在服务首次读取后生效，修改已有值需重启。凭据仅在服务端读取，不放在前端或源码包中。

通用工作台点击“用模型生成转换流程”才调用模型。默认发送自然语言指令、表头、字段类型/空值数量和目标约束。仅在用户勾选后，发送每份源表前 3 条非空记录。通用模型请求 60 秒超时，不自动重试，不静默回退。2026-10-12 已使用有效 DeepSeek 配置完成真实模型验收：原始表头及变化表头两组模拟案例均动态生成代码并通过执行、异常决策、三种格式回读和数据扰动核对。请求模型为 deepseek-chat，供应商实际响应模型记录为 deepseek-flash。密钥不要提交到源码包。

原有人事工作台由用户明确勾选模型辅助模式，只发送指令和表头，超时 45 秒。请不要在自然语言指令或表头里放不希望发送的内容。

通用模型生成 JSON 计划、目标约束和动态 Python 清洗代码。代码只能调用公开表格函数，由 AST 解释器执行，不使用 `eval`/`exec`，不能导入模块、访问属性、文件或网络。数值用 Decimal 解析和比较，导出受 Excel 15 位有效数字范围约束，并做内容回读验证。详细策略见 [Prompt 策略](docs/通用AgentPrompt策略.md) 与 [沙箱安全说明](docs/动态代码沙箱安全说明.md)。

## 通用转换演示

1. 打开首页，点击“载入双系统演示”。源表 A 是中文表头 XLSX，源表 B 是英文字段 GBK CSV，目标为 HR 空白 XLSX 模板。演示流程明确标记“未调用模型”；也可以点击模型按钮重新动态规划。
2. 核对目标类型约束。工号为文本，日期为 YYYYMMDD，金额为非负数，手机号为 11 位数字，工号为唯一键。
3. 勾选确认并执行。7 条源记录中，负金额剔除 1 条，完全重复去重 1 条，预览 5 条输出，工号 0004 的手机号异常导致暂停导出。
4. 在模拟案例中将该手机号核实为 `13800138001`，选择“修正此值”并提交。全部约束通过后可导出。
5. 选择 XLS、XLSX 或 CSV。CSV 可选 UTF-8（有/无 BOM）、GB18030、GBK；不可编码的字符会中止导出，不会静默替换为问号。所有格式都回读验证列序、行数及内容。
6. 下载 `import.*`、`audit.json`、`workflow.py` 或结果整包。审计保存输入哈希、原始映射值、源行号、筛选/去重理由、人工决策和生成代码。原始文件保持不变。
7. 保存成功流程，再上传同类新文件，选择已保存流程复用。表头不匹配时要求重新规划；人工修正的手机号不会硬编码进模板，新文件会重新校验。

自有文件至少需要源表 A 与只含表头的目标模板，源表 B 可选。支持两表合并与精确左关联，列名及规则从当前输入动态生成。当前开放函数支持重命名、裁剪字段、空白清理、字面替换、类型/日期转换、条件筛选、去重、明确地址拆分、常量填充与关联；任意工资公式、自由 Pandas 或缺失行政区推断不在可执行能力内，模型应询问而不是虚构结果。

异常中的目标值可人工修正或明确跳过。源公式行、无法确定的筛选比较只允许跳过，或修正源文件后重传，防止绕过筛选条件。结果大于预览行数时仍导出全量，完整溯源见审计文件。

通用输入限单文件 10 MB、5000 条数据、60 列、单工作表、单行表头；两表合并最多 10000 条。表头行可选第 1–20 行，不接受重复/空表头、合并单元格、XLSX 宏和外部链接。XLS 含公式时拒绝读取未核实缓存值。未知数值型工号不自动补零。源/目标表头以下划线开头的列属于保留命名，须改名。

XLSX 导出保留所上传模板的表名、表头之前内容、列宽与首个空白行样式；XLS/CSV 是符合目标列序的新文件，不复制模板外观。日期按目标约束输出文本（便于老系统的 YYYYMMDD 导入），金额为 Excel 数值。CSV 文本执行公式保护，危险首字符前增加单引号，精确业务值保存在审计 JSON。

## 原有人事工作台

以下请假/加班功能从左侧进入“请假结算 / 加班筛选”。其输入与导出契约与通用模式独立。

## 请假结算演示

1. 选择“年假抵扣与事假转换”，点击“载入模拟案例”。输入为两份 CSV 与一份空白 XLSX 模板。
2. 使用默认指令解析，也可启用配置好的模型。核对字段映射和目标列，每个模板列必须明确绑定输出字段或常量。
3. 确认 2026-09-01 至 2026-09-30、审批通过状态、假期类型及余额口径。勾选确认，运行计算。
4. 正常申请共 6.05 天，年假抵扣 3.30 天，转事假 2.75 天，生成 6 条导入记录。请假源表 15 行：正常 5、异常 6、排除 2、去重 1、空行 1。余额表 5 行：有效 3、关联隔离 2。异常清单共 8 条源行记录。
5. 查看逐行核算、异常清单、行数对账，下载导入表或结果 ZIP。
6. 将 `HR_年假余额_模拟.csv` 中 0001 的余额 3.00 改为 4.00，以“HR 年假余额”角色上传新文件。重新核对并确认配置，结果应变为年假 4.30 天、事假 1.75 天。原导出文件不变。这一步验证答案从当前文件计算。

余额必须是所选期间开始前、尚未扣减本批申请的期初余额。按工号、开始日期、单据编号顺序分配。只把确认的假期类型纳入结算，默认年假和事假。源表天数为权威值，不按日期跨度推算工作日。

## 加班筛选演示

选择“加班记录筛选”后重新载入模拟案例。默认指令：

```text
筛选已通过审批的加班记录。部门：研发部；日期：2026-09-01 至 2026-09-30。
```

确认后输出 2 条记录，总计 3.75 小时。财务部、范围外日期及未通过记录被排除，重复记录去重，25 小时记录进入异常清单。

本地解析支持两个固定业务类型。部门用 `部门：完整名称` 表达，日期给出两个明确年月日。不支持相对日期、任意公式或按姓名代替工号关联。未识别附加要求不会执行，必须核对完整计划。未知审批状态不会被视为通过。

## 输入与导出契约

- 源文件：UTF-8 / GB18030 CSV、TSV 或 XLSX。每个 XLSX 一张表，单行非重复表头，可指定第 1 至 20 行为表头。最多 5000 条数据、60 列、10 MB，解压体积上限 50 MB。末尾仅格式空行忽略，数据区域内空行计数。
- 不支持旧 XLS、宏、外部链接或合并单元格。源数据公式和 Excel 错误所在行隔离，避免使用未核实缓存结果。数字型工号隔离，防止前导零已丢失。
- 数值必须为非负十进制，最多两位小数，最长有效范围 1000000000；天数与小时必须大于零。单日小时上限 24。非法数值不会当作零。
- 目标为空白、单工作表 XLSX 模板。模板数据区含历史数据则拒绝导出。保持表名、表头原文、列序、列宽、现有校验和表头之前内容，工号写为文本、时长写为数值、日期写为日期类型；请核对模板日期显示格式。
- 必需输出字段：请假为工号、开始日期、结束日期、假期类型、天数；加班为工号、日期、小时数。模板其他列可以映射姓名、部门、来源单据或固定文本。
- 模板新数据行复制首个空白行的单元格样式；不自动扩展 Excel 表对象、命名区域、打印区或数据验证范围。需要这些功能时应在模板预设足够范围，并单独完成真实导入验收。

所有导入文本按文本类型写入 XLSX。CSV 审计文本具有公式保护，可能增加首位单引号；原始值同时保留在完整 JSON 审计中。

## 异常与审计

按工号精确关联，不做同名猜测。相同编号且内容一致时去重；内容冲突时隔离全部副本。缺余额、姓名冲突、跨期申请、未知状态等会隔离该工号的全部候选记录，避免部分错误扭曲连续扣减；其他员工继续处理。这是保守隔离策略，可能要求用户先修正源表再处理该员工。

每条源行在正常、异常、筛选排除、去重、空行中仅占一类；每轮检查行数守恒。导出结果目录 `data/<运行编号>/` 包含：

```text
import.xlsx       目标导入表，只含正常业务记录
exceptions.csv    异常与源行号
ledger.csv        每笔扣减或加班记录
audit.json        计划、输入哈希、映射、明细、异常和排除理由
result.zip        上述四个文件的整包
```

每次运行保存独立快照，不覆盖历史。文件解析与上传会话仅在内存，服务重启后需重新上传；已经写入的结果可以继续按原下载链接读取。使用 `BRIDGE_DATA_DIR` 环境变量可修改结果位置。运行目录没有自动清理或业务余额回写功能。

## 自动化验证

```bash
.venv/bin/python -m unittest discover -s tests -v
```

无 pytest 或模型密钥依赖，不调用收费接口。当前 62 项测试覆盖原有人事功能以及通用合并、动态字段、精确关联、异常决策、模板复用、真实 XLS 回读、四种 CSV 编码、代码越权拦截、完整 HTTP 导出和历史快照。验收记录分别见 `docs/验收记录.md` 与 `docs/通用转换验收记录.md`。

## 结构与范围

```text
app.py          本机 HTTP 服务、会话与导出快照
core.py         解析、字段契约、Decimal 引擎与模板导出
planner.py      本地指令解析和可选模型规划
universal.py    通用 Schema 约束、LLM 代码生成、隔离执行及格式导出
universal_api.py 通用任务状态、异常恢复和流程记忆
sandbox.py      受限 Python AST 解释器与表格函数
desktop.py      原生桌面窗口及本机服务生命周期
static/         无 CDN 的界面
samples/        模拟输入、两份模板、独立公式核算
tests/          unittest 测试
docs/           实测记录与演示说明
```

本版本为本机单人应用，未实现多人鉴权、企业审批、任意脚本执行、任意新业务运算、真实 HR 上传导入或 ERP/OA API 集成。模型动态规划接口与受限执行已实现；DeepSeek 真实调用已通过两组模拟案例验收；Windows 原生窗口与 EXE 打包尚未实机验证。实际验收范围以随附记录为准。第三方库通过 requirements 文件安装，遵循各自许可证。源码交付包排除密钥、用户数据、虚拟环境和缓存。
